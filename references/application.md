# Application submission

Use these instructions only when the user asks to complete or submit an application.

## Authorization boundary

- A request to draft, tailor, review, or prepare materials does not authorize submission.
- A clear request to apply to a named vacancy authorizes one submission to that vacancy using verified information.
- A batch request authorizes only the vacancies explicitly included in that batch.
- Do not reuse authorization for another role, company, or later application.
- If wording such as “help me apply” is ambiguous about submission, prepare the materials and ask before the final submission action.

Stop and ask when the application introduces a material choice not already authorized or supported, including compensation, relocation, visa status, work authorization, notice period, travel, background checks, legal attestations, conflicts of interest, or willingness to accept specific employment terms.

## Form completion

Use available browser or application capabilities without relying on vendor-specific tool names or fragile page hacks.

- Attach the correct final artifact where the form supports it.
- Answer screening questions only from the verified candidate profile.
- Preserve the user's wording for sensitive or subjective answers.
- Leave optional marketing, newsletter, talent-community, and data-sharing consent unchecked unless the user requests them.
- Accept only consent required for the requested submission and call out unusual terms.
- Do not create an account, reset credentials, accept paid services, or enroll in unrelated programs without explicit authorization.
- Never ask the user to send a password. Let the user complete authentication, multi-factor prompts, or CAPTCHA challenges directly.
- Do not bypass access controls or anti-automation mechanisms.

If the platform does not support the requested attachment or field format, use the supported route and tell the user exactly what was and was not included. Do not make permanent changes to an existing public profile or stored resume unless the user separately requests them.

## Pre-submit check

Immediately before submission, verify:

- company, role, location, and vacancy identifier;
- candidate identity and contact fields;
- attached file name and visible document content;
- every screening answer;
- required consent versus optional consent;
- absence of unverified claims and unresolved placeholders.

If all required facts are verified and the user's request clearly authorized this submission, proceed without requesting redundant confirmation. Otherwise stop at the last reversible step and ask one concise question.

## Result

Report one of:

- submitted successfully, with destination and attached artifacts;
- prepared but not submitted, with the exact blocker;
- submission failed, with the observed error and any safe next step.

Do not claim success based only on a button click; look for a confirmation state, receipt, or other reliable evidence.
